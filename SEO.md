# SEO и приватность при обновлении игры

Основной публичный адрес — https://zhenya.olegluzin.ru/. Публична только игра с уже согласованными персонажами. Исходные фотографии, возраст ребёнка, новые семейные сведения, комнаты, коллекции и личные страницы не входят в SEO-публикацию. Не открывайте закрытые материалы ради поиска или AI-ответов.

## Проверки каждого выпуска

Перед упаковкой запускаются игровые проверки и `node tests/seo.cjs`. Они проверяют постоянный H1, title и description, canonical, Open Graph, Twitter Card, JSON-LD, число уровней и управление, состав публичных файлов, карту сайта, политику роботов и правила редиректов. В GitHub эти проверки также запускаются при push и pull request.

Если меняются функции игры, обновите постоянное видимое описание, метаданные и нейтральную обложку вместе. Изменение количества уровней остановит проверку описания. Новые файлы в dist остановят выпуск до проверки их назначения и добавления в разрешённый список `scripts/public-files.json`. Добавлять файл в этот список можно только после проверки, что он предназначен для действующей публичной аудитории. Исходные фото и служебные документы туда не добавляются.

Архив создаётся только после успешных проверок:

```sh
python3 scripts/build-release.py ../deployment/zhenya-beget-seo.zip
```

Если Node.js не находится в PATH, передайте путь через `--node`. Скрипт архивирует только явно разрешённые файлы и сохраняет контрольные суммы рядом. Не архивируйте dist целиком: в прежней приватной рабочей копии там есть служебная документация.

## Особенности публикации на Beget

Beget обрабатывает существующие статические файлы через nginx; .htaccess применяется в Apache. Поэтому исходник остаётся статическим `dist/index.html`, а пакет для Beget содержит сгенерированный `index.php`, отдающий этот же HTML. Запрос непосредственно к `/index.php` перенаправляется на главную. Правила .htaccess перенаправляют `/index.html`, `www` и HTTP на основной адрес, сохраняют query-параметры и не превращают отсутствующие страницы в главную. Для HTTP с www Beget сначала включает HTTPS, затем Apache убирает www: допустима проверенная цепочка из двух постоянных редиректов.

На сервере не должно оставаться физического `public_html/index.html`: сохраните прежний файл за пределами public_html перед первым выпуском этого пакета. Иначе nginx сможет обойти редирект `/index.html`. Убедитесь, что для домена игры включён редирект HTTP → HTTPS в настройках Beget: эта настройка распространяется и на статические ресурсы. Другие сайты аккаунта не меняются.

Архивы, резервные копии и отчёты храните за пределами public_html. Перед заменой опубликованных файлов сохраните текущую версию и её .htaccess. Сохраняйте `Options -Indexes` и существующий контроль доступа. Не используйте резервную публикацию Sites для Beget-выпуска; у неё отдельные исходники и аудитория.

После загрузки запускайте обязательную проверку именно опубликованного сайта:

```sh
node tests/seo.cjs --live --report ../deployment/seo-live-check.json
```

Для сетевых запросов нужен curl с проверкой TLS; вход в кабинеты владельца не требуется. Она проверяет HTTP/HTTPS и www, постоянные редиректы index-файлов, сохранение параметров, отсутствие циклов, исходный HTML, совпадение опубликованных ресурсов с исходниками, robots.txt, sitemap, отсутствие неожиданного X-Robots-Tag noindex и корректные 404. Служебный METRIKA.md должен возвращать 403 или 404. В дополнение проверьте страницу без JavaScript, начало игры и мобильную компоновку. Сбой этого шага означает, что выпуск не подтверждён, даже если архив успешно загрузился.

## Политика поиска и обучение

Robots.txt сохраняет прежний доступ роботов к публичной игре и указывает sitemap с одной главной страницей. Его изменение не является способом сделать приватные страницы доступными. Noindex не заменяет авторизацию. В этом проекте нет отдельной публичной страницы ребёнка и в JSON-LD не создаются семейные профили, рейтинги или отзывы.

Проверка robots.txt фиксирует текущую согласованную политику. Если владелец позднее введёт отдельные ограничения поиска, обучения или приватные маршруты, обновите и политику, и её регрессионные проверки одним изменением; не снимайте запреты автоматически из-за ошибки SEO-проверки. Проверяйте контроль доступа на сервере отдельно от HTML-метатегов.

Резервная публикация Sites на момент проверки 30 сентября 2026 года доступна только владельцу. Аудитория сохранена. При изменении её настроек проверяйте реальную политику доступа через Sites, не по локальному .htaccess. Закрытую резервную версию не делайте публичной для обнаружения поиском.

## Проверки кабинетов владельца

Успешные технические проверки не доказывают индексацию, позиции или цитирование. Google Search Console, Яндекс Вебмастер и Bing Webmaster Tools проверяются отдельно при наличии доступа: статус URL, выбранный canonical, последний обход, исключения и поисковые показы. Реальные посещения роботов подтверждаются логами и проверкой их IP или обратного DNS, а не одной строкой User-Agent.

Не обещайте попадание в обучение моделей, знания без поиска или AI-ответы. llms.txt не является обязательным условием этого выпуска. Настройки поисковых кабинетов и фактическое индексирование описывайте отдельно от проверки кода и публикации.

Технические основания: [Beget о HTTPS и обработке статических файлов](https://beget.com/ru/kb/how-to/sites/podklyuchenie-ssl-k-sajtu), [Google о canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [Google о AI-функциях поиска](https://developers.google.com/search/docs/appearance/ai-features).
